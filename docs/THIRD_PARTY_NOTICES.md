## FastEdge runtime and Wasm redistribution: review required

The generated `geo-page/wasm/geo-page.wasm` is a binary distribution, not merely the application TypeScript. The FastEdge JS SDK's pinned build sources include [StarlingMonkey at `4dc05f3e4723497608d150a57b3bda0604de4781`](https://github.com/bytecodealliance/StarlingMonkey/tree/4dc05f3e4723497608d150a57b3bda0604de4781) ([Apache-2.0 text](../third_party/starlingmonkey/LICENSE)) and a [Firefox/SpiderMonkey source tree at `FIREFOX_147_0_4_RELEASE_STARLING`](https://github.com/bytecodealliance/firefox/tree/FIREFOX_147_0_4_RELEASE_STARLING), which contains MPL-2.0-covered code ([MPL text](../third_party/spidermonkey/MPL-2.0.txt)). The runtime and build tools can contain further libraries and notices. The exact complete set and any corresponding-source / modification / notice obligations for the built Wasm have **not** been verified here.

Before distributing a Wasm binary, independently inventory that binary and its linked components, obtain the corresponding source and notices for the precise build, determine any Apache, MPL and other applicable obligations, and include required notices/source availability or offers as appropriate. The npm SBOM alone does not enumerate compiled runtime internals. Do not assume that retaining these few license files completes compliance.

## npm SBOM and build/test dependencies

[`sbom.cdx.json`](sbom.cdx.json) is a CycloneDX inventory generated by `npm run sbom` from `package-lock.json`, using npm 10.9.8. It lists 375 npm components, including optional platform variants and build/test tools; it is **not** a statement that each component is shipped in the Worker bundle. npm metadata may be incomplete or wrong (as with `fastedge-test`), and the SBOM does not cover the whole cloud platform or nested precompiled Wasm internals.

Examples requiring extra attention if actually redistributed include `@img/sharp-libvips-*` (LGPL-3.0-or-later), some `@img/sharp-*` combinations, and `lightningcss` variants (MPL-2.0). They occur in the development/test dependency graph; their presence in the lockfile alone does not establish their inclusion in a Worker deployment. Check the precise shipped artifact and all applicable source, notice, replacement and relinking requirements. Pin, monitor and audit dependencies regularly; a zero-vulnerability `npm audit` result only reflects that registry's known advisories at the time of the check.
